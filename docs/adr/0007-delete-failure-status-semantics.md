# ADR-0007 — DELETE 失败状态码语义

- **日期**: 2026-11-10
- **状态**: 已接受
- **修订**: 明确 [SPEC.md](../../SPEC.md) §8 S11 的 DELETE 失败语义; 术语见 [CONTEXT.md](../../CONTEXT.md) "DELETE 失败语义".

## 背景

DELETE 是软删除: 对象先复制到回收站再删除. 集合删除可能部分失败; RFC 4918 §9.6.1 用 207 表示成员资源失败, 并允许请求整体失败时返回 4xx/5xx. 早期实现为统一错误解析, 单对象和集合目标失败也返回 207, 但 207 的语义是成员级, 客户端仍要把 207 当失败处理.

## 决策

- **成员失败** (集合内的文件或嵌套目录标记) → 207 Multi-Status; 列出失败成员; 保留其所有祖先与集合目标.
- **单文件 (非集合) 失败** → 500.
- **集合目标自身失败** (空集合, 或所有成员成功后标记仍失败) → 500.
- 207 只承载成员失败; 目标不作为 207 条目.
- 失败的单文件 DELETE 在返回 500 前仍执行机会式回收站清理 (约 10% 采样), 与成功路径一致.
- 500 响应为纯文本错误; 客户端按非 2xx 处理.

## 其它已评估方案

- **统一 207**: 拒. 207 的语义是成员级; 单对象客户端可能把 2xx 当成功; 客户端需要额外特判.
- **所有失败用 4xx/5xx**: 拒. 集合部分失败需要逐成员状态, 207 是 WebDAV 的机制.

## 后果

- 第三方客户端对单文件/集合目标失败看到 500, 更接近常规 HTTP 语义.
- 207 响应体只列成员失败; 祖先和目标保留但不列为失败.
- SPEC S11, CONTEXT 术语, `delete.ts` / `move.ts` 注释同步.
- 回归测试覆盖: 嵌套祖先保留, 单文件 500, 空集合目标 500, MOVE 转发 500.
