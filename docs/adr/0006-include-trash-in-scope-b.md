# ADR-0006 — 回收站纳入 Scope B

- **日期**: 2026-11-10
- **状态**: 已接受
- **修订**: 取代 [ADR-0003](./0003-simplify-to-single-credential-jwt-cookie.md) §7 中将回收站排除在 Scope B 之外的范围判断. [CONTEXT.md](../../CONTEXT.md) 与 [SPEC.md](../../SPEC.md) 已同步.

## 背景

Scope B 于 2026-05-22 锁定时, 回收站被列为范围外 (ADR-0003 §7, CONTEXT/SPEC/PLAN 同). 此后代码已实现软删除回收站: DELETE 将对象移入 `_$r2webdav$/trash/<timestamp>/`, 保留 14 天; `/trash` 页面支持查看/恢复/彻底删除; 过期条目在后续 DELETE 请求中按约 10% 概率清理. README 已公开记录该功能. 继续在范围文档中写"不做回收站"会误导部署者与后续实现者.

## 决策

将回收站纳入 Scope B, 按当前实现作为受支持功能维护:

- DELETE 为软删除: 先复制到回收站, 再删除原对象.
- 保留 14 天; 无定时任务, 过期条目在后续 DELETE 请求中机会式清理 (约 10% 采样).
- `/trash` 支持查看/恢复/彻底删除; 恢复冲突返回 409.
- 回收站对象位于内部命名空间, PROPFIND 不可见.
- DELETE 的软删除复制受 R2 单次 PUT 5 GiB 上限约束; 超大对象仍需 rclone/S3.

## 其它已评估方案

- **移除回收站, 回到直接 R2 delete**: 拒. 功能已实现并公开, 删除可恢复对单用户网盘有实际价值; 移除会造成行为回退.
- **保留"范围外但已实现"的例外**: 拒. 范围文档与 README/代码长期矛盾, 后来者无法判断该功能是否受支持、是否可改.

## 后果

- 回收站进入受支持面: 后续改动需保持 `/trash` 页面、软删除语义、14 天 TTL 与测试.
- SPEC 的成功标准 S11 从"直接 R2 delete"改为软删除/恢复语义.
- DELETE 的 5 GiB 单次 PUT 限制在 README 与实现注释中保持一致.
- 无新增依赖、无 D1/KV; 仍只用 R2.
