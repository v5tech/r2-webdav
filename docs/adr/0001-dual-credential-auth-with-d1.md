# ADR-0001 — 鉴权采用双轨凭据 (Web 主密码 + WebDAV 应用令牌), 持久化统一在 D1

- **日期**: 2026-05-21
- **状态**: ⛔ **Superseded by [ADR-0003](./0003-simplify-to-single-credential-jwt-cookie.md) (2026-05-22)**

> **本决策已废止.** 在更深入评估单用户场景后, 双轨凭据与 D1 持久化被判定为过度工程. 当前生效方案见 ADR-0003. 本文件保留作为决策演化记录.

---

## 背景

原项目使用 Cloudflare Pages 环境变量 `WEBDAV_USERNAME` / `WEBDAV_PASSWORD` 作为唯一凭据, 对所有 `/webdav/*` 请求做 Basic auth 字符串等值比较 (`functions/webdav/[[path]].ts:50-70`). 该方案存在多项缺陷: 主密码明文出现在每个第三方客户端的每次请求 Header 中; 无吊销手段; 字符串等值比较非常量时间; 无审计能力区分请求来源.

本次二次开发明确要求保留第三方 WebDAV 客户端 (Cx File Explorer / rclone / Windows 资源管理器映射等) 的可用性, 同时升级鉴权.

## 决策

引入两类生命周期独立的凭据, 哈希后统一存于 Cloudflare D1 表 `credentials`:

1. **Web 主密码** — 所有者用于浏览器登录的口令, Argon2id 哈希. 登录成功换发短期 **会话 cookie** (HttpOnly).
2. **应用令牌** — 为每个 WebDAV 客户端单独签发的长随机字符串. 每条令牌带可读标签、创建/末次使用时间、可单独吊销.

Web UI 的 API 调用走会话 cookie. WebDAV `/webdav/*` 仍走 Basic auth 协议格式, 但 password 字段必须是应用令牌; 服务端将提交值哈希后与 D1 比对, 使用常量时间比较.

## 其它已评估方案

- **方案 B — 凭据值统一**: 主密码 = WebDAV 客户端填的密码. 否决原因: 主密码会被每个第三方客户端以明文/弱加密存于本地 (Android 文件管理器、rclone config); 无法局部吊销 (单台设备失窃只能改主密码连带让所有客户端重配); 审计日志无法区分请求来源.
- **方案 C — Cloudflare Access 托管**: 整站置于 Zero Trust 后. 否决原因: 第三方 WebDAV 客户端无法执行浏览器 OAuth 跳转, 与"保留 WebDAV 客户端"硬冲突.
- **方案 D — 纯 Bearer 令牌 + localStorage**: 否决原因: 易被 XSS 偷取; 无注销/吊销 UX 抓手; 单一密钥泄漏即全失守.

## 后果

**正面**:

- 第三方 WebDAV 客户端无需改造 (Basic auth 协议格式保留).
- 主密码不再出现在 HTTP 请求中.
- 每个客户端独立吊销, 设备丢失不连累其他.
- 审计日志可按令牌标签溯源.

**负面/代价**:

- 引入 D1 依赖与 schema 维护负担.
- UI 需新增"应用令牌管理"页签 (生成/标签/吊销).
- 服务端鉴权中间件复杂度上升 (按路径前缀分流到会话校验或令牌校验).
- 初次部署需引导所有者完成"设置主密码 + 生成至少一个令牌"流程, 不再是开箱即用.

**不可逆性**:

- 一旦签发应用令牌, 模型改回单凭据会强制所有 WebDAV 客户端重新配置.
- D1 表结构变更需要迁移脚本.
